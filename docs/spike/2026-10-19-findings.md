## 额外发现

1. **「安装源」设为自定义地址会污染整次安装**：用户把安装源设成「自定义地址」并填入了仓库地址后，pnpm 把 profile 里**其他已装插件**（dsh-better-sidebar、dsh-plugin-whale-pet 等）也按 `https://github.com/yang051211/dsh-plugin-store/<包名>` 去解析，全部 404。DSH 却把它报成「无法连接 github.com」（日志：`~/.dsh/profiles/desktop/.plugin-manager/logs/operation-Bh27sL/pnpm.log`）。安装说明里要提醒：GitHub 地址只填在输入框里，安装源保持「npm 官方源」或「中国大陆镜像源」。
2. **只填包名会去 npm 上找**：`dsh-plugin-store` 没有发布到 npm，只填包名会提示「未找到相关插件」，属于预期行为。安装说明必须写完整的 `github:` 地址。
3. **用路径挂载时要指向文件**：本机冒烟环境中，用 `--patch` 按路径挂载时，`name` 必须写到 `lib/index.js`，写目录会报 `ERR_UNSUPPORTED_DIR_IMPORT`。通过包管理器安装的不受影响。
4. **整页面板与标签页的分工**：插件页切换标签的方法没有对外开放（`pluginNavigation` 只提供 `openBundle`），整页面板也拿不到 `install`。所以整页面板负责「逛」，要安装时需要把用户交接到插件页的「商城」标签页。具体交接方式由计划 3 设计。

## 对设计的影响

- §6.1.1 GitHub 分发：已验证可行，写法为 `github:<owner>/<repo>#<tag>`。
- §6.4 读取方式：采用 Host 路由（`ctx.webServer.register`），一个包、一行 patch。
- §2 目标 0（入口）：整页面板 + 侧边栏入口 + 首次自动打开都已验证；插件页标签页作为安装位置。
- §4 反目标：商城必须自带错误边界，出错时显示提示和「重试」，不能留白屏。
