# 生态家园改为开放目录：设计

日期：2026-10-26　状态：待用户确认

## 1. 要做什么、为什么

商店从「35 个人工审核过的精选插件」改成「npm 上所有合格的 DSH 插件」的开放目录，预计约 4800 个。用户的决定（2026-10-26）：

| 问题 | 决定 |
|---|---|
| 审核 | 不审核；商店上所有关于审核的文字去掉 |
| 收录范围 | 符合条件的全收（不设 1000 上限） |
| 有问题的插件 | 全收，不做屏蔽名单 |
| 「会联网 / 读写文件 / 执行命令」标记 | 保留，改叫「自动检测」，由扫描器生成，只作参考 |
| 现有 35 个的手写内容（中文标题、场景、装完怎么用） | 全部改成自动生成，手写内容删除 |

**不做（反目标）**：任何「已审核」「人工读过源码」「安全」之类的承诺；屏蔽名单；翻译插件描述。

## 2. 收录条件

每天自动重算，满足全部条件即收录：

1. 是真正的 DSH 插件包：package.json 有 `dsh` 字段（bundle 声明），或包内带 `cordis.patch.yml`。
2. 有源码仓库或主页（`repository` / `homepage`）。
3. `engines.dsh` 为空，或者兼容配置里写的「当前 DSH 版本」（初值 `0.2.1-rc.2`，改一行配置即可）。
4. 最新版本发布于近 90 天内（滚动窗口，替代问答里的「8 月以来」固定日期）。

不满足的插件会自动下架，下次满足时自动回来。

## 3. 数据从哪来（每天一次，GitHub Actions）

| 步骤 | 做法 | 量级 |
|---|---|---|
| 发现 | npm 搜索接口按关键词 `dsh-plugin`、`deepseek-harness`、`dsh`、`cordis` 翻页，再并上已知包名 | 约 1 万个候选 |
| 包信息 | 拉 packument；按 `modified` 时间增量，只重拉有变化的 | 首次约 1 万次请求，之后每天几百次 |
| 自动检测 | 只下载**新出现的最新版本**的 tarball，跑现有扫描器（联网、读写文件、执行命令、Agent 工具、安装脚本） | 首次约 4800 个，分多轮跑，每轮上限可配；没扫完的显示「尚未检测」 |
| 下载量 | npm 下载量批量接口（非 scope 包每次 128 个；scope 包逐个） | 每天约 2500 次请求 |
| 星标 | GitHub API，每天按最旧优先刷新一部分（受 API 额度限制） | 每天约 800 个 |
| 分类 | 按关键词和描述的规则自动归到现有分类，归不进的放「其他」 | — |

不再依赖第三方索引（REALOIYO），它只在开发时用来核对我们发现的结果有没有漏。

## 4. 发布的数据

| 文件 | 内容 | 用途 |
|---|---|---|
| `market/index.json` | 标准 format-1 索引，每个插件只带最新版本；`store` 扩展字段放首发时间、下载量、星标、自动检测结果 | DSH 官方「发现」页和商店界面读同一份（估计 3–4 MB，Host 上限放宽到 16 MB） |
| `market/plugins/<名>.json` | 单个插件的版本列表、自动检测证据 | 打开详情页时才加载；只在版本变化时重写，控制 git 历史增长 |
| README | 不入库，详情页实时从 jsDelivr 读 `npm/<包>@<版本>/README.md` | — |

## 5. 界面

| 页面 | 改动 |
|---|---|
| 顶部 | 首页 / 全部插件 / 关于（去掉「场景」） |
| 首页 | 搜索框；本周热门（按下载量）、最近更新、新上架三个区，各 8 张卡 |
| 全部插件 | 分类侧栏（带数量）；排序：热门 / 最近更新 / 新上架 / 星标；分页，每页 30；只看兼容的开关 |
| 卡片 | 去掉「审过版本」，显示最新版本 |
| 详情页 | 去掉审核面板、审核说明、「装完怎么用」；新增「自动检测」面板，并注明「由程序扫描源码自动得出，可能不准，不代表安全审查」；README 标签页实时加载 |
| 关于 | 重写：这是什么、数据来源、多久刷新一次、「自动检测」是什么意思、怎么安装、怎么反馈 |

安装仍然走 DSH 官方安装对话框，装的是最新版。商店自身的自更新提示不变。

## 6. 删除的东西

- `catalog/catalog.yaml` 里的审核、功能、用法、场景、精选、手写标题；只保留站点配置（当前 DSH 版本、关键词列表、每轮扫描上限、商店自身版本）。
- `catalog/decisions.md`、审核用的 icons-curated、上游追踪工具 `updates.mjs`、每日追踪工作流和它的 Issue（由每日构建取代）。
- 界面里的审核文案、`reviewedVersion` 等字段，以及相关测试；测试按新模块重写。

## 7. 风险

| 风险 | 处理 |
|---|---|
| 收录了恶意或劣质插件 | 用户已接受；关于页和详情页明说「未经审核」，自动检测结果可见 |
| 首轮扫描量大 | 分轮跑，每轮上限可配，未扫的标「尚未检测」 |
| npm / GitHub 限流 | 增量拉取、按天分摊，失败的下轮重试；单个包失败不影响整体构建 |
| 仓库体积膨胀 | 详情文件只在版本变化时重写；README 不入库 |
| 4800 张卡渲染卡顿 | 分页，首页只渲染 24 张 |
