# 生态家园成为插件总入口：设计

日期：2026-10-27　状态：待用户确认　目标版本：v0.3.0

## 1. 要做什么、为什么

用户想把生态家园当成插件的总入口：浏览、已安装、更新都在生态家园里完成，并且可以选择「只保留生态家园」——侧边栏和插件页上都看不到官方的入口和标签。

用户的决定（2026-10-27）：

| 问题 | 决定 |
|---|---|
| 已安装插件、更新提醒 | 放进生态家园 |
| 侧边栏「插件」和「生态家园」两个入口 | 开关开启时只留「生态家园」 |
| 插件页上「已安装 / 生态家园」两个标签和官方标题 | 开关开启时隐藏 |
| 开关默认 | **关闭**，即和现在一样 |
| 开关位置 | 生态家园「已安装」页右上角，名称「只保留生态家园」 |
| 其他插件的更新方式 | ~~打开官方页面里这个插件的页面~~（2026-10-27 改：官方页面不给第三方插件更新）**在生态家园里直接更新**：确认后调用插件管理器装新版本，重启 DSH 生效；生态家园自己仍走 `github:` 一键更新 |

**不做（反目标）**：
- 不重写官方插件页，不取代它的「已安装」标签内容。
- 不绕过官方安装对话框安装新插件：安装一律走插件页标签的 `install()`。例外是已装插件的更新（见 4.2），官方对话框拒绝按包名重装，只能由生态家园直接调用插件管理器。
- 不改官方插件（DSH 自带的那些）的安装和更新方式。
- 不改 DSH 文件，不打补丁；只用 DSH 公开的插槽和接口，外加一段可随时关掉的样式。

## 2. 已核实的事实（DSH 0.2.1-rc.2）

| 事实 | 出处 |
|---|---|
| 插件页「已安装」标签是页面自带的，不是插槽条目，插件无法删除它；第三方只能在它后面加标签（`plugins.tab`） | `dsh-client-ui-plugin-manager` 的 `slot-contract.d.ts` |
| 标签页拿到的 owner 能力只有两个：`install(target)` 打开官方安装对话框；`openPackage(name)` 切到「已安装」并打开某个插件自己的页面 | 同上，`PluginTabProps` |
| 官方「插件」侧边栏入口注册在 `sidebar.panellist`，`id: 'plugins'`，`order: 0`，默认优先级 0 | 官方 `client.js` |
| 列表插槽支持「覆盖」：同一个 `id` 可以有多个条目，优先级数值最小的那个显示；注册返回的 disposer 撤掉后，下一个自动显示 | `dsh-client-ui-slots` 的 `SlotCore.register` 说明 |
| 插件管理器远程接口：`listBundles()`、`setBundleEnabled(name, enabled)`、`removeBundle(name)` 等，返回 `ChangeResult`，其中 `application` 区分 `applied` 和 `restart-required` | `dsh-plugin-manager` 类型 |
| 官方页面的做法：启用/停用直接调用，不确认；卸载先弹确认（标题「卸载『{name}』？」，说明「卸载后它提供的功能会消失。」）再调用 `removeBundle` | 官方 `client.js` |
| `BundleInfo` 有 `name`、`version`、`enabled`、`installed`、`official`、`availability`（`installation` / `profile` / `missing`）、`meta`、`description` | `dsh-plugin-manager` 类型 |
| 官方页面顶部（标题「插件」+ 说明 + 右侧「添加插件」工具栏）和标签栏用的是 CSS Module 类名，带随版本变化的前缀，例如 `X_2TxG_pageHead`、`X_2TxG_pageHeading`、`X_2TxG_pageTabs` | 官方 `client.js` 内嵌样式 |
| 「添加插件」工具栏只在官方「已安装」标签上显示（`hidden: !onInstalled`），切到「生态家园」标签后就看不到 | 官方 `client.js` |
| `install(target)` 没有返回值，打开对话框后无法得知用户是装完了还是取消了 | `PluginTabProps` |
| 开启热重载（HMR）时，`installBundle` 拒绝按包名重装已安装的包（`already-installed`），换版本要先卸载再安装；`github:` 地址要等 pnpm 装完才知道包名，所以不受影响（生态家园自更新因此可用） | `dsh-plugin-manager` README、`lib/index.js` |
| 现在的生态家园对其他插件的「有更新」按钮调用 `openPackage`，打开官方页面里这个插件的页面 | 本仓库 `src/client/ui/StoreApp.tsx` |

## 3. 入口和导航

### 3.1 去掉独立整页面板

生态家园不再注册自己的 `main` 面板，也不再需要「整页面板不能安装、交给插件页」的交接（`handoff.ts`、`HandoffToast`、面板模式的 `StoreApp`）。所有界面都在插件页的「生态家园」标签里，安装直接调用 `install()`。

### 3.2 侧边栏

| 开关 | 侧边栏 |
|---|---|
| 关闭（默认） | 官方「插件」照旧；另有「生态家园」入口（女仆图标），点击后打开插件页并切到「生态家园」标签 |
| 开启 | 用覆盖机制注册 `id: 'plugins'`、优先级比官方低（例如 `-1`）的条目，显示女仆图标和「生态家园」；官方「插件」入口不再显示。点击打开插件页并切到「生态家园」标签 |

生态家园被停用或卸载时，我们的条目随之撤掉，官方入口自动回来。

开关关闭时，「生态家园」入口如何在没有自己面板的情况下打开插件页，交给实现者决定（例如保留一个极小的占位面板，激活后立即 `selectPanel('plugins')` 再切标签）。要求：点击后用户看到的是插件页的「生态家园」标签，不出现空白页。

### 3.3 切到「生态家园」标签

官方没有提供切标签的接口，沿用现有的 `selectTabWhenReady`（按标签文字找到并点击）。

| 场景 | 开关关闭 | 开关开启 |
|---|---|---|
| 点侧边栏「生态家园」 | 切到「生态家园」 | 切到「生态家园」 |
| 点侧边栏官方「插件」 | 官方默认行为（停在「已安装」） | （官方入口已被替换，不存在） |
| 首次安装生态家园后 | 打开插件页并切到「生态家园」（替代现在的「首次自动打开整页面板」） | 同左 |
| 从官方插件设置页返回 | 官方默认行为 | 回到「生态家园」 |
| 官方「已安装」**列表**出现（例如装完插件后官方强制切过去） | 官方默认行为 | 自动切回「生态家园」的「已安装」页；官方某个插件自己的页面（`openPackage` 打开的）不切 |

### 3.4 生态家园内的导航

顶部标签：首页 / 全部插件 / **已安装** / 关于。「已安装」带角标，显示可更新的数量（0 不显示）。

## 4. 已安装页

### 4.1 列表

- 数据来自 `listBundles()` 中 `installed: true` 的条目，随 `plugin-manager/changed` 事件和重连刷新（现有 `subscribeInstalled` 机制）。
- 分两组：**有新版本**（排在最前）、**其他**。官方插件（`official: true`）单列一组「DSH 自带」，只显示，不提供更新和卸载；点「设置」用 `openPackage`。
- 每行：图标（目录里有就用目录的）、标题（目录里有就用目录标题，否则 `meta` 或包名）、包名、当前版本、启用状态。

### 4.2 更新提醒

- 新版本来源：
  1. 在目录里的插件：目录里的 `dist-tags.latest`。
  2. 不在目录里、但能确认是 npm 安装的插件：向**用户在 DSH 里设置的安装源**（`pluginManager.registries`）查 `dist-tags.latest`。由 Host 新增一个只读路由，只查已安装的包名，结果缓存。
  3. 其他来源（`github:`、本地 link、无法判断来源）：不查，显示「来源不是 npm，无法检查更新」。
- 判定：两边都是合法 semver，且新版本大于当前版本。
- 有新版本的行显示「1.2.0 → 1.3.0」和「更新」按钮。点击先弹生态家园自己的确认框（新旧版本、审核提醒），确认后调用 `pluginManager.installBundle("name@latest")`，结果「重启 DSH 后生效」。
  - 原定的「打开官方页面」已放弃：官方对话框的 `inspect` 对已安装的包名一律拒绝（`already-installed`），官方页面也没有第三方插件的更新按钮。
  - 开启热重载时 `installBundle` 也拒绝按包名重装：提示「先卸载，再安装新版本」。
  - 新版本有待批准的安装脚本（`pendingBuilds`）时：列出包名，提示到官方对话框里卸载重装。
- 不做「全部更新」：`install()` 不告诉我们对话框的结果，无法一个接一个地排队。
- 生态家园自身的更新沿用现有自更新提示（`github:` 地址，一键更新）。

### 4.3 从地址安装（仅开关开启时）

开关开启时官方标签栏被隐藏，「添加插件」工具栏也只在官方「已安装」标签上显示，用户就没有地方输入 `github:` 等地址了。所以开关开启时，「已安装」页顶部加一个输入框和「安装」按钮，调用 `install({ spec })`，由官方安装对话框完成安装。开关关闭时不显示，用户照旧用官方的「添加插件」。

### 4.4 启用、停用、卸载、设置

| 操作 | 实现 |
|---|---|
| 启用 / 停用 | 开关，直接调用 `setBundleEnabled`，不确认（与官方一致） |
| 卸载 | 先弹确认，文案与官方一致；确认后调用 `removeBundle` |
| 设置 | 调用 `openPackage(name)`，进入官方页面中这个插件的页面 |
| 结果提示 | `applied` 静默刷新；`restart-required` 提示「重启 DSH 后生效」；失败显示错误原文 |
| `availability: 'missing'` 的条目 | 不提供开关，只提供「设置」（交给官方页面处理） |

生态家园自己（`dsh-startide`）在列表中不提供停用和卸载，避免用户从自己里面把自己关掉；要停用或卸载就去官方页面。

## 5. 开关「只保留生态家园」

- 位置：「已安装」页右上角。旁边一句说明：「开启后侧边栏只显示生态家园，插件页隐藏官方标题和标签栏；关闭即恢复。」
- 存储：浏览器 `localStorage`，每台电脑分别设置；读写失败视为关闭。
- 切换立即生效，不需要重启：注册或撤掉侧边栏覆盖条目，注入或移除隐藏样式。

### 5.1 隐藏什么

开关开启且插件页正显示时：

- 隐藏官方标题和说明（`pageHeading`）以及标签栏（`pageTabs`）。
- 「添加插件」工具栏不用管：它只在官方「已安装」标签上出现，而开关开启时官方列表一出现就会切回生态家园（3.3）。从地址安装改由 4.3 的输入框负责。
- 官方插件设置页（`openPackage` 打开的页面）不隐藏任何东西，它有自己的返回按钮。

### 5.2 选择器

官方类名带随版本变化的前缀，选择器按后缀匹配（例如 `[class*="_pageTabs"]`），并限定在插件页内，避免误伤别的页面。

失效时的表现：选择器匹配不到，就什么都不隐藏，页面和开关关闭时一样，功能不受影响。实现者要保证「匹配不到」只会导致不隐藏，不会导致隐藏错东西（例如不能用过宽的选择器）。
